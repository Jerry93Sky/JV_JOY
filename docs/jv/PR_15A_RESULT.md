# PR_15A — редактор JV-заказа: результаты и ограничения

База: опубликованный `feature/jv-full-ui`, коммит `b2017c9444cf722133607169fa571450c410b7d2`. Draft PR #5 остаётся открытым. Редактор выполняет реальные расчёты, но PR_15A **остаётся PARTIAL**: полный набор вариантов комплектации и parity всех селекторов не подтверждены. Настоящий browser E2E выполнен, см. [отчёт](./JV_UI_BROWSER_E2E_REPORT.md).

## Функциональность

- Защищённый маршрут `/jv/orders/new` и пункт меню для `OWNER`/`ADMIN`; backend независимо проверяет те же роли.
- До семи позиций с уникальными слотами 1–7: семейство, количество, добавление, копирование, удаление и изменение порядка отображения. Копия получает новый ID и свободный слот; перестановка не меняет слот.
- Формы Line, Zigzag, Slider L3/L5/X3/X5 и Front показывают разрешённые сервером поля. Начальные значения получены из подтверждённого контрольного сценария выбранного профиля и явно обозначены как пример, который пользователь должен проверить. Технологические настройки и цены пользователь не задаёт.
- Профили COMPLETATION и RETAIL имеют отдельные серверные данные. Изменение профиля сохраняет позиции и совместимые пользовательские значения, загружает соответствующую конфигурацию и сбрасывает старый результат.
- Страница использует `calculateJvPreview` и реальный `POST /api/jv/orders/calculate-preview`; отмена запроса и номер поколения защищают от позднего ответа. Изменение данных сбрасывает старую цену. COMPLETE показывает серверный точный итог, PARTIAL показывает диагностику и подтверждённые промежуточные суммы без итоговой цены.
- Неполные/неверные числа и количество проверяются на клиенте; сервер остаётся окончательным источником проверки. Ошибки HTTP и сети показываются пользователю. Вычисления стоимости во frontend отсутствуют.

## Контракт пользовательских полей

`GET /api/jv/orders/form-config?profile=COMPLETATION|RETAIL` выдаёт `JV-UI-INPUTS-2`, версию правил, примеры полей и серверные метаданные с подписями, источниками и признаками ограничений. Прайсы, коммерческие snapshots и вложенные настройки не выдаются. Все версии POST, включая `JV-UI-INPUTS-1` и legacy, проверяют поддерживаемые варианты, недоступные дверные настройки Front и единый F28. Сервер клонирует шаблон выбранного профиля и не принимает дополнительные настройки клиента. Неподтверждённые варианты, ранее допускавшиеся старыми форматами, теперь отклоняются.

Тесты подтверждают отклонение подмены `settings.P2` и `bomOptions.selectorControls.I25`, несовпадающей версии схемы и отсутствие доступа без разрешённой роли. Для всех 12 сценариев PR_13E новый компактный формат возвращает тот же результат движка, что и прежний формат при одинаковых входах.

## Ограничения и дальнейшая работа

- Транспортные варианты 1 и 2 доступны, 3 отключён для смешанного заказа. Списки Front получены из книг, но альтернативная фурнитура отключена до проверки её коммерческой parity. Полный реестр и ограничения: [JV_UI_SELECTOR_MAPPING.md](./JV_UI_SELECTOR_MAPPING.md).
- Front слот 7 при F28=2 разрешён для серверного контекста B26=1 после дополнительной проверки двух книг; подробности в [PR_15A_B26_RESULT.md](./PR_15A_B26_RESULT.md). B26 остаётся серверным параметром.
- В примере профиля Front настройки двери зависят от серверных технологических ограничений; ошибка проверки возвращается пользователю, а не заменяется приближённым расчётом.
- Отображение полной спецификации, раскроя, стекла, работ и подробного trace отложено на PR_15B; постоянное хранение заказов — на последующий этап.
- Интеграционный тест использует React Test Renderer и настоящий локальный HTTP Fastify/JV Engine; отдельный browser E2E использует Chrome. Оба работают с временным JWT без production DB.
