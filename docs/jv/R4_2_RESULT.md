# R4.2 — результат и ограничения

## Реализация

- Автосохранение черновика через 1,5 с после последнего изменения, ручное сохранение, состояния сохранения и сериализация запросов. Создание использует ключ идемпотентности, уникальный в пределах автора; повтор создания не создаёт второй заказ.
- Для этой вкладки неподтверждённые изменения сохраняются в `sessionStorage` и предлагаются к восстановлению после перезагрузки. При 409 автосохранение останавливается: можно открыть серверную версию после предупреждения или создать отдельный заказ из локальных данных. Ошибка сети сохраняет данные в форме и позволяет повторить запрос.
- Сервер сравнивает версию и содержимое под блокировкой строки; неизменившийся черновик не создаёт ревизию. История доступна с JSON-предпросмотром; восстановление выполняется с подтверждением, проверкой версии и новой транзакционной ревизией. Результат расчёта сбрасывается.
- Шаблоны PostgreSQL хранят имя, автора, даты, профиль, версии и входные данные. Обычный шаблон содержит одну позицию; Front с дверью разрешён только как проверенный семислотовый заказ и применяется только к пустому заказу. Для одиночного шаблона требуется совместимый профиль и версии. Расчётная цена не сохраняется.
- Миграция `20261116190000_jv_order_autosave_templates` добавляет `JvOrder.creationKey` и таблицу `JvTemplate`. Маршруты защищены существующими ролями OWNER/ADMIN. Формулы JV и Excel не менялись.

## Проверки

- Изолированная PostgreSQL: успешно применены все 28 миграций с нуля; отдельно восстановлен резервный снимок до R4.1 и последовательно применены миграции R4.1 и R4.2. Демонстрационная БД не мигрировалась.
- PostgreSQL API: 2 теста прошли: конкурирующие сохранения и 409, идемпотентное создание, отсутствие лишней ревизии, восстановление версии, шаблоны семи семейств и Front с дверью, запрет неподдерживаемого одиночного Front с дверью и отказ USER.
- Chrome на изолированной базе: автоматическое создание и debounce; повторное открытие; восстановление ревизии; создание/применение шаблона; семислотовый Front с дверью и COMPLETE; две вкладки и 409 с сохранением локальной правки; ошибка сети и повтор; восстановление после перезагрузки до debounce; потерянный ответ POST и идемпотентное восстановление; редактирование во время задержанного POST; добавление и перестановка, оба профиля, Undo/Redo.
- Существующие проверки: 205 JV тестов, 14 API тестов, 53 fixtures, backend/frontend builds, shared typecheck, SSR smoke, HTTP integration и Chrome E2E прошли. Ошибка `window is not defined`, выявленная первой попыткой HTTP integration, исправлена и проверка повторена успешно. Предупреждение Vite о JS-чанке более 500 КБ сохраняется.

## Ограничения и последующие проверки

- Переход по ссылке из редактора с неподтверждёнными изменениями требует подтверждения; переход системной кнопкой Back внутри SPA отдельно не заблокирован и остаётся непроверенным.
- Восстановление через `sessionStorage` относится к той же вкладке и не гарантирует восстановление после закрытия вкладки, очистки браузера или отсутствия доступа к хранилищу. Для этого пока нужно дождаться подтверждённого сохранения; `beforeunload` только предупреждает.
- Не все сочетания медленной сети, перезагрузки непосредственно во время восстановления ревизии, нескольких одновременно созданных шаблонов, FULL/PARTIAL и повторного расчёта после восстановления исследованы браузерными тестами. Тест перезагрузки в точности во время незавершённого запроса PUT не выполнен: конфликт при устаревшей версии должен оставлять локальные данные, но этот частный сценарий ещё проверить.
- Это Draft, а не подтверждение готовности к коммерческому релизу. Прайс/trace не фиксируются; повторный расчёт обязателен. Предыдущее ограничение командной палитры остаётся в `FINAL_UX_BACKLOG.md`.
