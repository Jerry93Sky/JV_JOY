# PR_05 — карта цен и расчёт себестоимости JV-Line

## Цель

Перенести только подтверждённые price/cost rules JV-Line поверх количественной спецификации PR_04. Не считать это основанием для полного расчёта коммерческой цены конструкции: скидки, наценки, монтаж и итоговые totals требуют отдельного подтверждения.

## Обязательные исходные правила

Использовать обе оригинальные книги и `LINE_MATERIAL_CATALOG.md`. До разработки кода для каждой поддержанной строки зафиксировать:

- источник цены в `Прайс-Line!E` и её единицу;
- конкретную формулу `Lx!P` (есть строки с делителем `Настройки!D2`, строки без него и отдельные делители, например `Настройки!L7`);
- сумму `Lx!Q`, вес `Lx!S`, покраску `Lx!V`, если применимо;
- различия workbook profile `COMPLETATION`/`RETAIL` и valid-from/version;
- все коэффициенты, скидки, наценки, округления и порядок операций;
- поведение Excel errors/blank prices и формульных текстов;
- подтверждённую связь SKU/unit с каталогом BMS.

Прайсы обеих книг — отдельные snapshot-версии. Не копировать реальные цены в общий quantity catalog и не подставлять значения из сохранённых formula caches как результат пересчёта.

## Работа

1. Собрать версионируемые snapshot-каталоги цен обеих книг, не меняя оригиналы.
2. Проверить каждую формулу цены и зависимость от настроек в Excel.
3. Зафиксировать Excel COM golden cases обеих книг и exact output cells для каждой реализуемой цены.
4. Реализовать cost rules отдельным DAG слоем поверх verified BOM lines; не менять geometry/quantity rules.
5. Применять цены только к строкам с подтверждёнными единицами, currency, делителями и quantity parity.
6. Представить детализированный trace: source price, price snapshot version, coefficient/rule IDs, line quantity, unit rate, extended amount.
7. Сохранить точные Excel binary/decimal differences. Округление разрешается только если подтверждено конкретным Excel expression или выбранной системной parity policy.
8. Не добавлять blanket price rule для всех SKU: формулы L1!P5:P44 различаются.

## Ограничения

- Не менять `/calculate`, Prisma, production DB или React UI без отдельного разрешения.
- Не вводить скидки, розничные наценки, монтаж, услуги или delivery totals без трассировки их исходных формул.
- Не выдавать частичный cost result как окончательную цену.
- Сохранить staged worktree и исходные `.xlsm` без изменений.

## Критерии готовности

- Каждый реализованный price line имеет exact Excel source/rule and price snapshot version.
- Комплектация и розница тестируются независимо.
- Excel пересчитывается на рабочих копиях с отключёнными макросами.
- Все сравнения, включая float representation differences, отчётливо зафиксированы без epsilon-маскировки.
- Нет регрессии действующего BMS.
