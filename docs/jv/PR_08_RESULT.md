# PR_08 — результат завершения коммерческой цепочки JV-Line

## Итог

Независимый модуль JV-Line теперь считает из исходных параметров и versioned snapshots клеевые коэффициенты, выбранное заполнение/стекло, покраску и итог Q52:Q58. Для изолированного слота JV-Line (Главная!Z11=1, Z12:Z17=0) он возвращает `COMPLETE` и доступную Q58 только при наличии всех поддержанных компонент и прохождении Excel guard. Legacy `/calculate`, Prisma, production DB и действующие алгоритмы GlasS не менялись.

Покрытие подтверждено 20 разнообразными сценариями, по 10 на каждую книгу, и двумя отдельными сценариями коммерческой ветви F28=2. Это не доказывает parity смешанного заказа нескольких систем и не даёт основания объявлять PR_08 полностью готовым к merge: браузерный smoke-test после авторизации в этой среде не выполнен.

## Новые правила и реализация

| Правило | Источник Excel | Реализация |
|---|---|---|
| Исходный селектор створок `Главная!L11` → `Главная!M11 = CEILING(L11,1)` → `L1!D5` | `Главная!M11`; L1!D5 ссылается на `Главная!M11` | `packages/shared/src/jv/line-calculator.ts`, точный decimal ceil к положительной значимости 1 и trace `JV.LINE.MAIN_LEAVES_CEILING` |
| Клей/активатор O5/O18 по расходу и целым упаковкам заказа | `Клей+акт!O5`, `Клей+акт!O18`; расходы JV-Line из `L1!O49/O50`, масштабирование `Главная!Z11` | `packages/shared/src/jv/adhesive-line.ts`; rational factors в `packages/shared/src/jv/pricing-line.ts` |
| Строки заполнения F43:F48, суммы G43:G49, D45, I55 и добавка D54/Q54 | `L1!C46:C51`, `D45:D51`, `F43:F48`, `G43:G49`, `I55`, `D54`, `Q54`; `Прайс-Стекло!D5:D16`; `Настройки!P19`, L17/L18/L21/L22/D32; прайс C23 | `packages/shared/src/jv/glass-line.ts` |
| Покраска V5:V18 и Q53 | `L1!O5:O12`, `V5:V18`, `Q53`; `Прайс-Line!G5:G12`; `Настройки!L9:L11`; `Прайс-сб+монт!C24` | `packages/shared/src/jv/paint-line.ts` |
| Коммерческие итоги Q56/Q58 и ветка F28=2 | `L1!Q52:Q58`, `Главная!F28`, `Прайс-сб+монт!C25`, X5, D6/D7 | `packages/shared/src/jv/commercial-line.ts` |
| Публичная orchestration и trace всех ветвей | см. таблицу выше | `packages/shared/src/jv/line-calculator.ts`, экспорты в `packages/shared/src/jv/index.ts` |

Деньги/площади/множители в новых правилах вычисляются точными рациональными значениями. Денежные величины не проходят через JS `Number` и не округляются универсально. Никаких не подтверждённых формул или неявных нулей для отсутствующих прайсов не введено.

## Excel golden tests и результаты

Оригиналы книг проверены по SHA-256: комплектация `62dd6d49f059bef840b67713a0ea6a9f1dec0ec90cf364563cf423dac376d2d8`; розница `025d7e2911176ca0b0cdb445574565cd8e3f44d814905cd4c474999630c7ab41`. Все пересчёты сделаны Microsoft Excel 16 `CalculateFullRebuild` на временных копиях, с `AutomationSecurity=ForceDisable` и выключенными событиями.

`docs/jv/LINE_FULL_PRICE_PARITY.json` содержит 22 кейса и 154 сравнения Q52:Q58:

- 85 `EXACT`: рациональный десятичный результат движка совпадает с COM `Value2` десятичной записью.
- 69 `DISPLAY_MATCH`: точные числовые значения различаются из-за Excel binary64, но совпадает отображение до 2 знаков; они не маркируются численно эквивалентными.
- 0 `MISMATCH`, 0 `UNVERIFIED`.

20 кейсов — 10 на каждый профиль, с вариантами размеров, направлений, количества створок, парковки, специальных створок, услуг, селекторов стекла и финиша. Ещё два fresh Excel rebuild подтверждают F28=2 в обоих прайсах. Условия конфигураций и данные записаны в `docs/jv/fixtures/line-full-commercial-excel-golden.json` и `line-mode2-excel-golden.json`; скрипты запуска/сборки — `tools/jv/recalculate-line-commercial-golden.ps1`, `tools/jv/build-line-full-commercial-fixtures.mjs`, `tools/jv/build-line-price-parity-report.mjs`.

Сценарий с `Главная!L11=4.5` выявил необходимую входную нормализацию: Excel выдаёт `Главная!M11=L1!D5=5` по явной формуле CEILING. Это правило реализовано из исходной формулы и добавлено в сквозной тест; формульные выходы O15, O49/O50 и Q52:Q58 не передаются движку как входные значения.

## JV-Line Lab и ограничения

`apps/frontend/src/modules/jv-line/JVLineLabPage.tsx` вызывает общий `calculateLineConstruction` и показывает строки/итоги/trace с локальными снимками. UI использует JV Engine, не заглушку; production API и база не задействованы. Production `/calculate`, Prisma schema, сделки и существующие формулы BMS не менялись.

Локальный Vite поднялся, однако встроенный браузер Codex получил `ERR_CONNECTION_REFUSED` при доступе к loopback; запуск Computer Use для Edge был остановлен его runtime из-за неопределённого URL. Поэтому визуальный прогон страницы после авторизации, проверка редактирования полей и авторизационного сценария остаются неподтверждёнными. Подробность: `docs/jv/LINE_LAB_TEST_REPORT.md`.

## Остаточные риски и PR_09

1. Много-системный заказ не проверен: X5/ПРМ!AB25, минимальные расходы клея/покраски и распределение общего Q52 при одновременных ненулевых Z11:Z17 пока ограничены одной системой JV-Line.
2. Не заявляется полное покрытие всех формул XLSM, типов заполнения и всех технологических/валидационных ограничений. Сценарии проверяют только перечисленные ветви и исходные snapshot-версии.
3. Не проверен реальный интерактивный UI после входа; потребуется отдельная безопасная test-auth среда.
4. Не переносились расчёты JV-Zigzag, JV-Slider и JV-Front, а также legacy API integration.

Задачи следующего этапа перечислены в `docs/jv/PR_09_TASK.md`. PR_08 закрывает первую однослотовую JV-Line цепочку Q52:Q58 с 22 подтверждёнными Excel rebuild cases, но не закрывает смешанные системные заказы и визуальный smoke-test.
