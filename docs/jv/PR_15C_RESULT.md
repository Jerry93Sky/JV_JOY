## Продолжение: обзор и реальный JV benchmark

Chrome восстановил фиксированный семипозиционный дверной пример через Undo после очистки; семейство и доводчик оставались заблокированными, старый итог отсутствовал. Независимые production-сборки сравнивались на all-seven с BOM, trace, профилем и изменением ширины; результаты и ограничения в JV_UI_PERFORMANCE_REPORT.md. Исправлен выявленный визуально дефект: Login использовал тёмный жёсткий фон при светлой теме; после исправления обе темы просмотрены.

Изолированный скрипт `audit-jv-pages.mjs` снял `/login`, `/leads`, `/deals`, `/clients`, `/warehouse`, `/vendors`, `/systems`, `/finance`, `/settings`, `/jv/orders/new` в двух темах на 1440×900; все API искусственно возвращали 503, данные отсутствовали, БД не использовалась. Просмотрены обзорные изображения этих состояний и Login в обеих темах; тесты экранов с наполненными таблицами, реальными диалогами и статусами этим не заменяются. CI сохраняет исходные PNG и audit.json. Отсутствие FOUC в первом кадре, все случаи истории, более широкая визуальная приёмка и длинные профилировочные прогоны остаются открытыми; PR остаётся Draft.
