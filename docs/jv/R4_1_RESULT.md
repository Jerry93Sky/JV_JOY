# R4.1 — результат

Реализовано ручное создание и обновление черновиков, список, открытие, индикация изменений и просмотр JSON-снимков ревизий. PostgreSQL хранит заказ и ревизии; обновление и запись ревизии выполняются в одной транзакции с проверкой версии. Конфликт возвращает 409 и не очищает форму. Автор определяется JWT; маршруты доступны OWNER/ADMIN. В заказе сохраняются входы, порядок, слоты, профиль, UI/rules версии и необязательные ссылки на контакт/сделку. При открытии результат сбрасывается, trace handle не сохраняется; новый расчёт выполняется явно.

Проверено: отдельная PostgreSQL с 27 миграциями; тест семи семейств, сохранения RETAIL и COMPLETATION, двух одновременных обновлений (200/409), истории и 401/403/400. Chrome: добавить конструкцию → сохранить → перезагрузить → открыть → изменить количество → сохранить версию 2 → перезагрузить и проверить значение. 205 JV и 14 API тестов, сборки frontend/backend, shared typecheck, HTTP integration, fixtures и smoke запускались отдельно.

Не подтверждены отдельные браузерные сценарии Front с дверью и PARTIAL при сохранении; сохранённая цена в R4.1 не хранится и потому не отображается. Автосохранение, восстановление произвольной ревизии, шаблоны и snapshots цен/расчётов отложены до R4.2. Существующая демонстрационная PostgreSQL не мигрировалась. Перед обновлением стенда нужен согласованный план резервного копирования и миграции.
