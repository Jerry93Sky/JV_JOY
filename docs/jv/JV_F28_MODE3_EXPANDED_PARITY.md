## Метод

На каждый сценарий создавалась отдельная временная копия оригинальной книги. Проверены SHA-256 до и после серии. Excel 16.0 пересчитал формулы через `CalculateFullRebuild` при отключённых макросах, событиях и обновлении внешних ссылок. Сценарии меняли первичные параметры. При попытке записать в формульную ячейку runner останавливается. Значения вычисляемых K и M перечитаны после пересчёта. У неактивных строк `Z=0`. Источник сведений о каждой ячейке — `Formula`, `Value2`, `Text` и `NumberFormat`. Для пустого B26 проверено истинное отсутствие содержимого, а COM CVErr и текстовые технологические ошибки записаны в отдельных полях.

Сравнение использует рациональный результат движка, точное сравнение binary64, сравнение округления до ближайшего binary64 и фактическое отображение. Строка технологической проверки I23 сравнивается как текст и отмечается отдельно от числовых измерений. При ошибке Excel и числовом результате ядра отмечается MISMATCH. При недоступности результата движка или несопоставимой ошибке отмечается UNVERIFIED. [Параметры, формулы, результаты и диагностика каждого сценария](JV_F28_MODE3_EXPANDED_PARITY.json)

### Минимальное воспроизведение MISMATCH

Сценарий `completation-front-slot1` из манифеста — один активный Front 3000×2200, `J11=4`, `L11=3`, `Z11=1`, `F28=3`, B26 физически пустая. Остальные `Z12:Z17=0`. Excel считает AA11 = 108096,57571740256, но `Клей+акт!O5 = N12/SUM(N5:N11)` и `O18 = N25/SUM(N18:N24)` дают `#ДЕЛ/0!` при нулевом общем расходе. Ошибка неактивных строк AA12:AA16 попадает в `AA18=SUM(AA11:AA17)`. Ядро суммирует активную позицию и даёт 108096,575717402584384576.

Контроль `completation-front-slot1-inactive-front` меняет первичные селекторы и параметры неактивных строк на допустимый Front и сохраняет их количество 0. O5 и O18 сохраняют ошибку, но неактивный Front не использует эти множители в цене. AA18 Excel становится 108096,57571740256. Аналогичный контроль пройден в рознице.

## Коммерческий допуск и следующий приоритет

Публичный коммерческий API по-прежнему принимает транспортные варианты 1 и 2. Допуск режима 3 остаётся закрыт. Причины — различие суммы при ошибке неактивных строк Excel, отсутствие в контракте **подтверждённого пустого B26** и блокировка режима 3 в отдельном оркестраторе Line + Zigzag. Ядро №24 требует версионного снимка B26, поэтому отсутствие снимка сохраняет отказ независимо от обнаруженного поведения самой книги.

Следующая группа — `Клей+акт!O5/O18 → цены неактивных строк → Главная!AA18` для одиночного Front, вместе с явно подтверждённым пустым B26. Нужно согласовать, отражает ли итог для изолированного заказа сумму только активных строк или должен воспроизводить ошибку Excel при нулевом общем расходе клея. После этого — точечная поддержка режима 3 в отдельном Line + Zigzag, проверка итогов, подсумм и сохранение блокировок составов вне подтверждённого контракта. R5.9 остаётся проектом процесса выпуска счёта.

## Воспроизведение

В PowerShell из корня checkout. Для воспроизведения отчёта требуется отдельный чистый checkout опубликованного SHA PR №24, доступ к обоим исходным XLSM и Excel 16.

```powershell
node tools/jv/prepare-f28-expanded.mjs manifest.local.json
& ./tools/jv/capture-f28-expanded.ps1 -ManifestPath manifest.local.json -OutputPath capture.local.json
node --experimental-strip-types tools/jv/compare-f28-expanded.mjs C:/work/jv-pr24 capture.local.json report.local.json
```

Параметр `-SourceDirectory` задаёт расположение оригиналов. Оригинальные XLSM, временные книги и локальные настройки отсутствуют в изменениях PR.
