# R5.3 — условия черновика КП

Владелец выбрал пять обязательных полей: получатель, реквизиты, условия оплаты, сроки и доставка. Поля вводятся вручную, без предзаполненных договорных значений.

- Сохранение условий создаёт новый черновик КП, связанный с прежним через `previousDraftId`; старый остаётся доступен. Сервер принимает только пять заполненных строк ограниченной длины, проверяет права и целостность прежнего КП и его снимка. Клиент не может передать новую стоимость.
- Предупреждение при попытке покинуть редактор или открыть другой документ с несохранёнными условиями; во время сохранения поля заблокированы. Восстановление текста после аварийного закрытия вкладки не реализовано.
- По решению владельца отображение суммы в КП — до копеек с пометкой «округлено», если точное значение не укладывается в копейки; при половине копейки используется округление от нуля. Операция выполняется только для показа над BigInt rational. Исходное точное значение хранится без изменения и раскрывается отдельно.
- Остаются не реализованы налоги, срок действия, согласование, печать, экспорт и выпуск/отправка КП. Черновик не считается выпущенным документом.

Проверены backend/frontend сборки, четыре PostgreSQL-теста, серверная проверка неполных условий, подмены цены и недостаточных прав, Chrome создание и повторное открытие новой версии, тест отображения суммы, существующая UI/HTTP регрессия и shared typecheck. Новых миграций нет; демо Docker не менялся.

## Важный результат проверки цены

Владелец обратил внимание на тестовую стоимость; проведён отдельный свежий пересчёт Excel. Выявлено расхождение настройки включения стоимости стекла: `LINE_PRICE_INVESTIGATION.md`. Пользователь подтвердил, что для комплектационного режима стекло по умолчанию не включается. В данной версии R5.3 поведение расчёта не менялось; до отдельного исправления и регрессии считать данное расхождение открытым и вручную проверять цену в КП.
