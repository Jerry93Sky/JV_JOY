# PR_03E — полный расчёт раскроя несущего профиля JV-Line

## Выполненная работа

По исходным формулам обеих книг перенесены 8 формул из блока `L1!C28:D32`, константа `C31=1`, затем необходимая downstream-формула `L1!O5`, которая превращает сумму отрезов в спецификационное количество профиля. Добавлен DAG-блок раскроя в shared JV-код; он потребляет готовые I26/I27/I25 и не пересчитывает геометрию дублирующим алгоритмом.

Реализованные выражения и code rule IDs:

| Правило / адрес | Формула или значение Excel | Реализация |
|---|---|---|
| `C28` / `JV.LINE.CUT_A_QUANTITY` | `=$D$6` | `packages/shared/src/jv/geometry/cutting.ts` |
| `D28` / `JV.LINE.CUT_A_LENGTH` | `=$I$26+Настройки!$P$2/2` | тот же модуль |
| `C29` / `JV.LINE.CUT_B_QUANTITY` | `=$D$6` | тот же модуль |
| `D29` / `JV.LINE.CUT_B_LENGTH` | `=$I$27+Настройки!$P$2/2-Настройки!$P$7` | тот же модуль |
| `C30` / `JV.LINE.CUT_E_QUANTITY` | `=$D$6` | тот же модуль |
| `D30` / `JV.LINE.CUT_E_LENGTH` | `=$I$26-Настройки!$P$6/2` | тот же модуль |
| `C31` / `JV.LINE.CUT_F_QUANTITY` | константа `1` | trace источника в том же модуле |
| `D31` / `JV.LINE.CUT_F_LENGTH` | `=$D$3-$D$6*(Настройки!$P$6+$D$30)` | тот же модуль |
| `D32` / `JV.LINE.CARRIER_TOTAL_CUT_LENGTH` | `=$C$28*$D$28+$C$29*$D$29+$C$30*$D$30+$C$31*$D$31` | тот же модуль |
| `O5` / `JV.LINE.CARRIER_PROFILE_MATERIAL_QUANTITY` | `=$D$32/1000+Настройки!$D$7/1000` | тот же модуль |

Итого: **9 формульных ячеек**, одна константа C31 и 10 вычислительных DAG-узлов. Операции раскроя не содержат ROUND/ROUNDUP/ROUNDDOWN/INT и не были снабжены выдуманными правилами округления. Деление пополам и преобразование мм→м выполняются точной десятичной арифметикой.

## Длины, количества и материал

Выход cutting-модуля включает для A/B/E/F отдельные `cutLength`, `quantity` и `totalCutLength`, исходные адреса обоих значений, суммарный D32 и материал-адаптер. Он указывает на код `LN-010`, наименование «Профиль несущий» и единицу `п.м` через проверенные ссылки `L1!L5:M5:N5 -> Прайс-Line!B5:C5:D5`. Количество для будущей спецификации вычисляется формулой O5. Стоимость, прайсы, складской раскрой на хлысты, стекло и полный BOM не реализовывались.

O5 напрямую потребляется далее формулами L1!Q5 (сумма строки материала), S5 (вес) и V5 (покраска). Эти денежные/массовые вычисления не перенесены. Документированное legacy правило LN-010 в `apps/backend/src/prisma/import-formulas.ts` использует упрощённый `round((width+100)/1000/cutCoeff,3)` и не совпадает со структурой Excel: D32 суммирует фактические резы по геометрии, O5 прибавляет припуск `Настройки!D7` и переводит результат в погонные метры. Legacy-формула не менялась.

## Пересчёт оригинальных формул в Excel

На Windows доступен Excel COM **16.0**. Пять сценариев для каждой исходной книги запускались на отдельных временных копиях. Runner отключает VBA через `AutomationSecurity=ForceDisable`, отключает события и внешние обновления, задаёт inputs на копии и выполняет полный `CalculateFullRebuild`. Оригинальные книги не изменены. Сохранённые формульные кэши не использовались как ожидаемые значения.

Первоначальный comparator отчитал 10/10 совпадений, но свежая проверка PR_04 показала, что O5 имеет exact equality только в 6/10 случаях. Геометрия, резы, D32 и SKU/name/unit совпадают 10/10; в 4 O5 cells сохранена разница Excel binary representation. Свежие raw значения, входы и source hashes лежат в [line-cutting-excel-golden.json](fixtures/line-cutting-excel-golden.json), сводка — [LINE_MATERIAL_PARITY.json](LINE_MATERIAL_PARITY.json).

## Остающиеся ограничения

- `Главная!C11` не подписана единицей измерения рядом с входной ячейкой. P1 показывает `мм` для настроек P2/P6/P7, E7 — `мм` для D7; в формулах геометрически ожидается совместимая единица ширины проёма. Caller указывает общую unit explicitly.
- Не выполнялась проверка полного BOM, всех вариантов Line и транзитивных price formulas. Позиция LN-010 — первый подтверждённый material result, не вся спецификация.
- Нельзя передавать D32/O5 в производственную базу или legacy `/calculate`: PR_03E остаётся изолированным shared calculation code.
- Другие профили/заполнения, дополнительные комплектующие, раскрой стандартных хлыстов, пильный пропил и остатки не включены в C28:D32 и требуют самостоятельного подтверждённого Excel-блока.

## Уточнение по повторному Excel-пересчёту (PR_04)

Свежий `CalculateFullRebuild` на временных копиях выявил, что старое утверждение «10/10 точных совпадений всех ячеек» было неверным для O5: в сценариях `line_double_with_park` и `line_special_sash_width` обе книги возвращают через Excel COM `5.537999999999999` и `6.404999999999999`; shared engine возвращает точные десятичные результаты `5.538` и `6.405`. Различие `8.881784197001252e-16` сохранено без округления/epsilon в `fixtures/line-cutting-excel-golden.json`. Геометрия, резы, D32, SKU, наименование и единица совпали. Итог O5 parity: 6 точных совпадений и 4 числовых представления с двоичным residue; см. `LINE_MATERIAL_PARITY.json`. Правило O5 в коде выражает исходный порядок `D32/1000 + D7/1000`; десятичный результат не подгоняется под double artefact Excel.
