# Front: дверь и фурнитура

Обновление: для одного строго ограниченного заказа с F7 и подтверждённой комбинацией fittings добавлен отдельный профиль; см. [JV_FRONT_DOOR_PROFILE_MAPPING.md](./JV_FRONT_DOOR_PROFILE_MAPPING.md). Списки других вариантов остаются закрытыми.

Excel 16.0 пересчитал 10 изолированных сценариев F1: `base`, `wide`, `door_one`, `transom`, `fittings` в каждой книге. Исходники сверены по SHA-256 и открыты как временные копии. Записаны значения C18:C24, D18:D19, материальные Q/R/S5:32, коммерческие ячейки и параметры заказа в `fixtures/front-commercial-r1-excel.json`. Сравнение: `FRONT_COMMERCIAL_R1_PARITY.json`, повторяется `node --experimental-strip-types tools/jv/compare-front-commercial-r1.mjs`.

Из 70 сравнений F1!S33/S36/S37/S38 и Главная!X11/Y11/AA11: 8 EXACT, 31 NUMERICALLY_EQUIVALENT, 31 DISPLAY_MATCH, 0 MISMATCH и 0 UNVERIFIED. DISPLAY_MATCH не означает точного равенства. В `fittings` обеих книг проверена одна конкретная комбинация: I42=2, C18=1, C19=2, C20=2, C21=2, C22=8, C23=10, C24=2, D18=1000, D19=2150; размеры и прочие входы записаны в источниках. Она подтверждает только этот сценарий F1 и не является подтверждением всех сочетаний или семи слотов.

Исправлена найденная ошибка: `F1!R27=IFERROR(INDEX('Прайс-Аксессуары'!D59:D61,$C$21-1),0)`. При C21=2 выбирается D59, ранее код выбирал D60. В обоих ценовых профилях добавлен тест адресов D59:D61 для C21=2:4; отдельная коммерческая parity C21=3:4 не заявляется. Сравнение сценария fittings после исправления прошло по семи коммерческим ячейкам каждого профиля.

Обычный серверный профиль имеет I42=1; отдельный профиль I42=2 ограничен проверенным примером. Произвольное изменение I42 через API запрещено. C21:24 и прочие не проверенные сочетания остаются LIMITED/EXCEL_PARITY_UNVERIFIED.
