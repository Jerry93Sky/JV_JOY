# Полная миграция расчётов Excel в JV Engine

## Приоритет

Расчётная логика обеих книг от 08.10.2026 имеет приоритет над R5.9, R6, новыми модулями BMS и визуальной полировкой. Существующие заказы и коммерческие документы продолжают работать с действующим контрактом. Допуск новых комбинаций требует реализованных правил для их области входов, независимых пересчётов и сверки ошибок.

## Первый реализованный срез — Line + Zigzag и F28=3

Основа ветки — `main` на `3c0e4b05aa775e4ac40573ac34b3cc85b2582ec7`. В отдельном оркестраторе `calculateMixedOrder` общий селектор `Главная!F28` теперь принимает 3. Расчёт сохраняет исходное правило: `Прайс-сб+монт!C25` начисляется через `L1!Q56` и `Z2!P42` только при F28=2. Проверка равного режима у всех позиций и отказ для других селекторов сохранены. Неполный Line по Q58 оставляет заказ PARTIAL без итоговой суммы.

Excel 16.0 `CalculateFullRebuild` отработал на шести временных копиях, по три сценария каждой книги. Сценарии используют заказ из Line и Zigzag в слотах 1 и 2. Размеры, количества, стекло, монтаж и дополнительная работа различаются. Первичные записи и вычисляемые K/M сверяются. Оригинальные файлы проверены по SHA-256. Всего 1 848 сравнений геометрии, раскроя, количества и стоимости материалов, SKU Zigzag, стекла, работ, монтажа, распределения и цены. 1 124 EXACT, в том числе 180 текстовых SKU, 278 NUMERICALLY_EQUIVALENT, 430 DISPLAY_MATCH, 16 MISMATCH, 0 UNVERIFIED. Все 18 сравнений строк AA11/AA12 и итога AA18 прошли в указанных категориях. Денежные строки BOM и подсуммы также прошли.

Два вида расхождений:

- В обеих книгах `Z2!K9` читает `Прайс-Line!B12` и показывает LN-070-A. `Z2!O9` берёт цену из E11, где карточка LN-060. Движок возвращает LN-060 с ценой из E11. Количество в каждой из шести проверок — 4 на конструкцию. Цена строки совпала, идентификатор закупаемого изделия требует отдельной сверки. Подстановка цены E12 изменила бы исходный расчёт.
- `Z2!H9`, `H16` и `H17` дали десять различий между точной рациональю и промежуточным binary64 Excel. В исходной книге эти значения не отображались. Для них нет подтверждения DISPLAY_MATCH. Проверенные количества и денежные ветви сохранили результаты.

Новые подтверждения и расхождения перечислены в [дополнении к матрице](FULL_EXCEL_COVERAGE_DELTA_LINE_ZIGZAG_F28_3.csv). Они относятся к новой ветке и не включены в базовый счётчик №23. Для вычислительных ветвей общий знаменатель пока отсутствует. Доступность в публичном API сохраняется для подтверждённых прежних вариантов, F28=3 возвращает HTTP 422. Код общего ядра №24 и исследование №26 остаются отдельными кандидатами.

## Воспроизведение и проверки

`pnpm test:jv` воспроизводит сравнение с сохранёнными независимыми снимками. Чтобы заново получить снимки, `node tools/jv/prepare-line-zigzag-f28-3.mjs <манифест>` создаёт список первичных записей и наблюдений. COM runner зафиксирован в [PR №26, SHA 14fd37a](https://github.com/Jerry93Sky/JV_JOY/blob/14fd37a6129b496dab04fa5e1f56a50273c964f9/tools/jv/capture-f28-expanded.ps1). Ему передаются `-ManifestPath`, `-OutputPath` и при необходимости `-SourceDirectory`. В CI Excel не требуется. Тесты используют захваченные формулы и результаты, движок получает параметры и версионные справочники.

Новая функциональная ветка основана на main. Интеграция требует независимого ревью и успешных проверок точного SHA. Демонстрационный Docker и PostgreSQL исключены из этой задачи.
