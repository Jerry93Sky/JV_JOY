# PR_09 — масштабирование расчётной цепочки JV

## Цель

Продолжить миграцию в существующем `packages/shared/src/jv`, сохраняя точную десятичную/рациональную арифметику и изоляцию от legacy `/calculate`, Prisma и production DB.

## Приоритеты

1. Разобрать смешанный заказ с двумя и более активными системными слотами: подтвердить формулу и распределение `X5`/`ПРМ!AB25`, групповые минимумы клея и покраски, Q52/Q53/Q54/Q56 при ненулевых `Z11:Z17`. Снять отдельные Excel 16 full-rebuild golden cases для обоих прайсов.
2. Укрепить публичный входной контракт: явные исходные селекторы Главная!L11, C11, H11/F28, проверенные переключатели и фактические источники геометрии. Проверить допустимые диапазоны UI data validation; отклонять недопустимый ввод без скрытых значений по умолчанию.
3. Разобрать неподдержанные ветви Q54 (другие типы заполнения/условия обработки), специальные стеклопакеты и дополнительные работы. Каждое правило подтверждать исходными формулами, каталогом и golden tests.
4. Выполнить браузерный UI smoke-test в безопасной тестовой авторизационной среде, проверить изменение пользовательских полей, результат и trace. Не использовать production сделки/БД.
5. Получить дополнительные границы и валидные технологические пределы JV-Line; документировать невалидные и граничные случаи отдельно от «Excel совпал».
6. После полного review — отдельное задание на интеграцию API; в PR_09 legacy endpoint и схема БД остаются вне области.

## Приёмка

- Каждый новый Q-итог прослеживается до формулы Excel, исходного ввода и версионированного справочника.
- Golden captures получены из временных копий с `CalculateFullRebuild`; исходные xlsm неизменны.
- Сравнения маркируют EXACT и DISPLAY_MATCH раздельно; MISMATCH не маскируются допуском.
- Расчёт остаётся детерминированным, без JS `Number` для денег, и сохраняет статус неполноты, когда ветвь не подтверждена.
