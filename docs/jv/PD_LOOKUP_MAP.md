# JV-Line: точная карта справочника ПД

## Источники и контроль идентичности

Книга `JV-комплектация 08.10.2026.xlsm` и книга `JV-розница 08.10.2026.xlsm` проверены раздельно. Формулы L1!D23/O15/I25/I26/I27 совпадают. Диапазоны ПД сравнивались по всем значениям и совпали полностью:

| Таблица | Excel диапазон | Размер | Ячеек | Формул | Непустых чисел | Ненулевых | Значения | SHA-256 данных |
|---|---|---:|---:|---:|---:|---:|---|---|
| Односторонняя | `ПД!D5:BA54` | 50×50 | 2500 | 0 | 2500 | 1225 | 0, 3, 5, 7 | `b5d818bf7e5151c7580cc36776303b973ee87077ed9b6833c289c2d6b0407a4b` |
| Двухсторонняя | `ПД!D61:BA110` | 50×50 | 2500 | 0 | 2500 | 1176 | 0, 4, 6, 8 | `a2695cf2b2b388e9089238182ea8e7d55923a887eb3a13899764b53ccc69fa3e` |

Все 5000 ячеек — числовые константы; пустых ячеек и формульных/ошибочных ячеек в двух диапазонах нет. Заголовки листа `ПД!C2:C4` и `C58:C60` описывают количество боковых защёлок для систем с паркуемой дверью, положение ПД и число створок. Они не содержат вычислений, используемых самим `INDEX`.

Версионированные данные извлечены в `packages/shared/src/jv/geometry/pd-catalog.ts`, версия `JV-PD-2026-10-08`. В файл внесён массив исходных значений; адрес исходной ячейки восстанавливается по координатам диапазона и записывается в результат/trace. Исходные книги не включены в код.

Связанная формула `L1!D6 = IF(Главная!$K$11<=2,Главная!$K$11,"НЕТ")` ограничивает фактический вход значением количества сторон 1/2 либо текстом `НЕТ`. В обеих сохранённых книгах `L1!C24` содержит константу `2`, не формулу; в Excel DataValidation коллекции листа L1 правил для D5/D6/C23/C24 нет. Возможную привязку C23 к форме-элементу управления по одному значению ячейки не утверждаем.

## Условия выбора и индексы

В обеих книгах `L1!O15` содержит:

```excel
=IF($D$23="НЕТ",$D$6+2,0)
 + IF(AND($D$23="ДА",$D$6=1),INDEX(ПД!$D$5:$BA$54,$D$5,$C$24),0)
 + IF(AND($D$23="ДА",$D$6=2),INDEX(ПД!$D$61:$BA$110,$D$5,$C$24),0)
```

`INDEX(array,row_num,column_num)` получает `row_num` из D5 и `column_num` из C24. Индексы Excel начинаются с 1. При индексе `(r,c)` фактическая ячейка равна:

- для D6=1: строка `5+r-1`, столбец `D+c-1`;
- для D6=2: строка `61+r-1`, столбец `D+c-1`.

| D6 | D5 (row_num) | C24 (column_num) | Выбранный адрес | Извлечённое значение |
|---:|---:|---:|---|---:|
| 1 | 2 | 2 | `ПД!E6` | 3 |
| 2 | 5 | 2 | `ПД!E65` | 6 |
| 1 | 2 | 1 | `ПД!D6` | 0 |
| 1 | 50 | 50 | `ПД!BA54` | 5 |
| 2 | 50 | 50 | `ПД!BA110` | 0 |

Если C23=false, D23 возвращает строку `НЕТ`; выбирается только D6+2, таблица ПД не индексируется. Если C23=true, D23 возвращает `ДА` при D5/D6>1 и обычную строку `ОШИБКА` иначе. Для этой строки все три сравнения O15 дают false, поэтому O15 равно 0. Деление на D6=0 — отдельная вычислительная ошибка Excel. Для `ДА` выбор матрицы ограничен точными сравнениями D6=1 или D6=2.

## Границы и ошибки

Извлечённые массивы покрывают допустимый индекс 1..50 по обоим направлениям. Индекс больше 50/отрицательный индекс даёт typed `LOOKUP_NOT_FOUND` с соответствием Excel `#REF!`. Индекс 0 не подменяется единичным элементом: Excel `INDEX` возвращает массив при нулевом row/column, а поведение пересечения массива в контексте O15 не проверено, поэтому получается `RULE_UNCONFIRMED`. Аналогично дробные индексы закрыты `RULE_UNCONFIRMED`, пока не подтверждено приведение дробной части самой Excel-версией. Статические исходные массивы не содержат пустых ячеек или Excel-ошибок; проверка значения при lookup оставлена для защиты от повреждённого каталога. Тестирование пустой/ошибочной ячейки из оригинала невозможно, так как таких значений в обоих источниках нет.

Поддерживаемое соответствие `C24` BMS-настройке пока не подтверждено: legacy `JV-Line` в `apps/backend/src/prisma/import-excel.ts` содержит ширину, высоту, створки и `hasSide`, но не параметр положения паркуемой двери. Для нового pure calculation API эти значения передаются явно. Единица измерения ячеек и матрицы в Excel явно не подписана и не назначается реализацией.
