# PR_10D — промежуточный результат Zigzag BOM

## Реализовано в этой итерации

Расширен `calculateZigzagBaseMaterialQuantities` точными правилами `Z1!N5`, `N8`, `N15`, `N33`:

- `N5 = D20/1000 + Настройки!D8/1000`, где D20 ссылается на ширину конструкции.
- `N8 = IF(D13="ДА", C21*D21/1000 + Настройки!D8/1000, 0)`; D13 вычисляется движком из входного индекса настройки и справочника `#1!F3:F4`, C21/D21 — исходные Excel-правила.
- `N15 = 1`, `N33 = 2` — константные количества исходного листа.

Вместе с прежними правилами поддерживаются 15 из 31 строк количества `N5:N35`. Ещё 16 остаются неподдержанными. P44 не рассчитывается: BOM неполон, цены не агрегируются.

## Excel-проверка

Выполнены 8 сценариев `CalculateFullRebuild` на временных копиях: обе книги, две размерные конфигурации, обе ветви D13. Проверено 256 сравнений: EXACT 168, DISPLAY_MATCH 0, NUMERICALLY_EQUIVALENT 0, MISMATCH 0, UNVERIFIED 88. Все реализованные целочисленные и конечные BOM-количества сравниваются точно. 88 UNVERIFIED — точные рациональные геометрические результаты с непериодической десятичной записью против строк Value2 Excel; погрешность/допуск не применяется.

## Остаются

Не реализованы N6/N7, N11/N12, N20:N26, N29:N31, N34/N35 и часть остальных строк. Они требуют восстановления промежуточной геометрии, селекторов D14:D17, справочников, ROUNDUP и заказного распределения расхода. Стоимостная цепочка P44 всё ещё блокируется неполным BOM, price lookup строками, P39:P43 и общими начислениями. Конструкция и заказы с Zigzag должны оставаться PARTIAL.
