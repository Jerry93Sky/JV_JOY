# R3.1 — Double-click row editing

> Матрицы R3.1 и R3.2 ниже сохранены как история на дату соответствующей итерации. Актуальный статус приведён в разделе R3.3 в конце документа.

## Область реализации

Общий обработчик игнорирует вложенные кнопки, ссылки, формы и touch; использует существующее действие редактирования. Строки: контакты, компании, товары, поставщики, пользователи, услуги, типы стекла, стёкла системы, параметры системы, формулы комплектующих, редактируемые по сроку приходы и заголовки систем в сделке. Административные справочники дополнительно проверяют роль OWNER/ADMIN, как серверные маршруты; ограничение срока прихода и `canEdit` сделки сохранены. Контакты, товары и компании используют существующую серверную политику requireAuth. Кнопки редактирования сохранены. У компаний одиночный переход отложен на 500 мс для распознавания двойного клика; медленный двойной клик вне этого интервала ещё требует проверки.

Лиды и карточки сделок имеют собственный переход в подробности, а редактирование их отдельных полей находится внутри карточки; общий редактор целой строки там не обнаружен. Списания и расчётные результаты не получили вымышленный редактор. Полная проверка всех вложенных экранов и прав не завершена.

## Роли, фокус и ошибки

- Реальный backend изолированной БД: POST OWNER и повышение USER до OWNER отклонены; ADMIN не изменяет другого OWNER, OWNER может изменить собственное имя и не может снять с себя роль. OWNER/ADMIN могут менять услугу, USER/GUEST получают 403. Изменение собственной роли OWNER теперь блокируется сервером и формой.
- Диалог товара: фактически проверены Tab, Shift+Tab, Escape и восстановление фокуса на кнопку; `r33-focus-check.mjs`. Фокус после закрытия кнопкой проверен fixture-тестом на контактах, товаре, пользователе и поставщике. В общий Dialog добавлено доступное имя кнопки закрытия.
- Сохранение товара после искусственного HTTP 500 и прихода после реального HTTP 403 оставляет диалог и значения; повторное сохранение успешно. Проверена защита от дублирования PATCH при двойном нажатии на сохранение товара. Проверено подтверждение удаления поставщика и его отмена на реальном backend в R3.1.
- NOT_RUN: реальные уведомления успеха/ошибки для всех форм, HTTP 400 для всех форм, возврат фокуса и клавиатура во всех остальных диалогах, браузерное масштабирование 125%/200% и физическое сенсорное устройство. Данные ограничения не заменяются результатами touch-эмуляции R3.2.

## Исправления и изоляция

P0: сохранение системы сделки без пересчёта раньше отправляло пустой состав и удаляло позиции. Теперь оно не передаёт состав, а API сохраняет прежние расчётные параметры, когда они не переданы. P1: backend теперь запрещает редактирование системы в закрытых этапах и проверяет принадлежность системы сделке; UI не переключает раскрытие при двойном клике. P1: предотвращена смена роли OWNER на другую. P1: исправлены возврат фокуса и отсутствие сообщения ошибки в формах товара, услуги и прихода; право редактирования прихода в UI совпадает с серверной ролью и сроком.

Для четырёх новых сценариев использовалась отдельная PostgreSQL в контейнере `jv-r33-isolated-db` с tmpfs, без Docker volumes и без демонстрационной базы.
