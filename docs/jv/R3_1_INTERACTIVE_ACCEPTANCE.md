# R3.1 — Double-click row editing

## Область реализации

Общий обработчик игнорирует вложенные кнопки, ссылки, формы и touch; использует существующее действие редактирования. Строки: контакты, компании, товары, поставщики, пользователи, услуги, типы стекла, стёкла системы, параметры системы, формулы комплектующих, редактируемые по сроку приходы и заголовки систем в сделке. Административные справочники дополнительно проверяют роль OWNER/ADMIN, как серверные маршруты; ограничение срока прихода и `canEdit` сделки сохранены. Контакты, товары и компании используют существующую серверную политику requireAuth. Кнопки редактирования сохранены. У компаний одиночный переход отложен на 500 мс для распознавания двойного клика; медленный двойной клик вне этого интервала ещё требует проверки.

Лиды и карточки сделок имеют собственный переход в подробности, а редактирование их отдельных полей находится внутри карточки; общий редактор целой строки там не обнаружен. Списания и расчётные результаты не получили вымышленный редактор. Полная проверка всех вложенных экранов и прав не завершена.

## Матрица интерактивной проверки

| Сценарий | Статус | Фактическое доказательство и ограничения |
|---|---|---|
| Контакт: создание, изменение, повторное открытие, отмена и удаление тестовой записи | PASS | Chrome 1440, реальный backend и демонстрационная БД; `r3-live-contact-check.mjs`, тестовая запись удалена. |
| Поставщик: то же, включая отмену подтверждения удаления | PASS | Chrome 1440, реальный backend; `r3-live-vendor-check.mjs`, тестовая запись удалена. |
| Контакт, товар, пользователь, поставщик: двойной клик, значения, карандаш, Escape, отмена | PASS | Chrome 1440, изолированные фиктивные ответы API; `r3-row-edit-check.mjs`. |
| Компания: двойной клик | PASS | Chrome 1440, фиктивный API; одиночный переход и изменяемая системная скорость двойного клика не полностью проверены. |
| GUEST: запрет двойного клика по поставщику | PASS | Chrome 1440, фиктивная авторизация; реальный запрет сервера остаётся без изменений. |
| Ошибка сохранения поставщика | PASS | Искусственный HTTP 500; диалог остаётся открыт и показывает сообщение об ошибке. |
| Вложенная кнопка и touch | PASS | Проверка синтетическими событиями; физические устройства и ссылки ещё не проверены. |
| Лиды, сделки, компании, товары, приходы, списания, системы, пользователи: полный CRUD | NOT_RUN | Нет подтверждённого полного цикла с реальным backend в этой итерации. |
| Остальные строки, фильтрация и сортировка, роли и навигация | NOT_RUN | Автоматические проверки охватывают не все варианты. |
| Диалоги, все темы/ширины, Tab, Shift+Tab, возврат фокуса, все уведомления | NOT_RUN | Частичное покрытие не означает полного прохождения. |
| Мобильные таблицы: мышь, touch, клавиатура, масштаб, скрытые вкладки | NOT_RUN | Требуется интерактивная проверка за пределами прежнего статичного аудита. |

Подтверждённые исправления: P1 — диалог поставщика без стандартной семантики и Escape переведён на существующий Dialog; ошибка сохранения отображается. Удаление поставщика теперь требует подтверждения. Визуальная доступность остальных диалогов и возврат фокуса остаются открытыми; нельзя утверждать отсутствие других P0/P1.

Ранний HTML-фон темы сохранён. JV Engine, арифметика, Prisma schema и Excel-эталоны не изменены. GitHub PR остаётся Draft. Рекомендация: R3 ещё не готов к окончательной приёмке, пока не выполнены оставшиеся интерактивные сценарии и решение владельца.
