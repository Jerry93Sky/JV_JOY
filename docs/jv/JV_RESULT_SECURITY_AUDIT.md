# Security audit — JV result v1

Legacy `serializeJvResult` recursively serializes all Engine fields, Maps/Sets, full nested family outputs, duplicated traces and potentially price snapshots/settings. It is restricted to OWNER/ADMIN but is not a safe DTO; compatibility endpoint deliberately remains. The new endpoint directly projects allowed fields and never serializes then removes arbitrary keys. Summary/position BOM, selected geometry, selected subtotals and diagnostics are included; internal snapshots, settings, calculations, trace inputs and catalog contents are not. Trace metadata retains rule, cell, sheet, workbook, step identifiers, scalar numeric result, references and diagnostics; nested results are omitted.

Tests use nested secret objects in top-level, BOM and trace inputs/results/source, verify these do not survive projection, PARTIAL omits total, enforce token and role checks, cross-user 404, page limits, cache expiry, FIFO eviction and oversized refusal. This is not a formal security audit: the legacy endpoint still exposes its full authorized payload, string diagnostics/labels originate from Engine, and production HTTP proxies/logging and tenant isolation need deployment review. Authorization scope is user ID, not a separate tenant model. No server-side price calculation changed.
