# PR_11A — результат реализации JV-Slider L3

## Реализовано

Добавлен `calculateSliderL3Geometry` в `packages/shared/src/jv/slider/geometry.ts`, экспортирован из JV Engine. Модуль выполняет точные rational/DAG правила для `S1!D31:D34`, `D43:D45`, `D37`, а также первую завершённую группу BOM `S1!K5` и `K7` (`S-010`, `SL-110`). Геометрия и количества считаются из параметров и снимка настроек; рассчитанные Excel значения не используются как входы.

Через Excel 16 `CalculateFullRebuild` на временных копиях подтверждены селекторные переходы F11=3..6, а parity геометрии и двух BOM количеств проведена для четырёх случаев (два размера/открывания × комплектация/розница): **36 EXACT, 0 MISMATCH, 0 UNVERIFIED**. Полный результат — `SLIDER_GEOMETRY_PARITY.json`.

## Проверки

- Slider unit tests: 3 passed.
- Полный `pnpm test:jv`: 113 passed, 0 failed.
- `pnpm typecheck:shared`: passed.

## Границы покрытия

Реализован вариант L3 (F11=3, C8=10, C9=3, C10=13). Таблица BOM `S1!5:46` (42 строки) снята с пересчётом для обеих книг; количества остальных 40 строк пока не перенесены. Не реализованы цены строк Slider, стекло/покраска/работы, общие расходы Slider и коммерческий `S1!M53`. Поэтому этот модуль подтверждает геометрию и две позиции количества, но не стоимость и не полный Slider заказ. Вне записанных Excel сценариев parity не заявляется.

Legacy `/calculate`, Prisma, production DB, Line/Zigzag calculators и Mixed Order не менялись. Исходные книги не изменялись.
