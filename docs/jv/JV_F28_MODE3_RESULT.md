# Excel parity транспорта F28=3

В оригинальных книгах `Главная!F28` связан со списком `#1!C29:C31`. Значение 3 подписано «Доставка на объект». Формулы L!Q56, Z!P42, S!M51 и F1:F6!S36 прибавляют C25, умноженную на долю площади, только при F28=2. `F7!S36` независимо проверяет `Главная!B26=2`.

Общее ядро семи семейств принимает 3 и применяет существующие формулы. Единый параметр должен совпадать по всем позициям при выборе режима 3. Для Front в слоте 7 требуется подтверждённый B26. Отсутствующий B26 возвращает `RULE_UNCONFIRMED`. Публичный API, интерфейс и отдельный расчёт Line+Zigzag сохраняют действующие ограничения. Прайсы, монтаж и другие доплаты сохранены.

## Независимый результат

Excel 16.0 `CalculateFullRebuild` на четырёх временных копиях. По два сценария на каждую книгу с B26=1 и B26=2. Перечитаны 352 записанных первичных значения. Профиль и SHA источника зафиксированы. Все четыре заказа вычислены полностью в ядре.

## Воспроизведение

В PowerShell из корня репозитория, с Excel 16.0. При необходимости передать пути к оригиналам параметрами `-CompletionWorkbook` и `-RetailWorkbook`.

```powershell
node tools/jv/prepare-transport-3-parity.mjs manifest.local.json
& ./tools/jv/capture-unified-order-all-seven-pr13e.ps1 -ManifestPath manifest.local.json -OutputPath capture.local.json
node --experimental-strip-types tools/jv/compare-transport-3-parity.mjs manifest.local.json capture.local.json replay.local.json
pnpm test:jv
```

Для снятия ограничения в публичном API нужны проверка одиночного Front, пустого B26, Line+Zigzag и сочетаний с дополнительными работами и монтажом.
