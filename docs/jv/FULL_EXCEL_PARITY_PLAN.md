# План полной Excel parity

## Воспроизводимый конвейер

1. Зафиксировать два источника по профилю и SHA-256. Каждый кейс содержит идентификатор, семейство, слот, версию книги, независимый список первичных записей, ожидаемые адреса и точные правила активации. Ошибочные кейсы явно помечаются.
2. Сделать отдельную временную копию для каждого кейса. Запускать Excel 16.0 с макросами и событиями выключенными, обновление внешних ссылок отключить. Прочитать записанные входы, вызвать `CalculateFullRebuild`, сохранить `Formula`, `Value2`, `Text`, `NumberFormat` и метаданные. Оригиналы используются только для чтения. Данные Excel ERROR фиксировать отдельно от отсутствующего значения.
3. Дать JV Engine первичные параметры, версионные прайсы и справочники. Снять рассчитанные адреса, точные рациональные значения, SKU, единицы, построчные суммы и trace. Сравнивать независимо подтверждённые выходы.
4. Использовать EXACT для равенства рационали сохранённому бинарному Value2, NUMERICALLY_EQUIVALENT для совпадения после однократного приведения к binary64, DISPLAY_MATCH для подтверждённого пользовательского отображения, MISMATCH для несовпадения, UNVERIFIED для отсутствующей или неподдерживаемой проверки. Для строк и ошибочных значений явно сравнивать состояние, текст или код Excel. Сохранять точный адрес, путь правила и сценарий.
5. Повторять статический реестр после изменения исходников или поступления артефактов. Для каждого расхождения сохранить минимальный воспроизводимый кейс и существующий полный контекст. Пройти тесты затронутого движка, API и исходных сценариев. Выкладывать сверки с указанием SHA, профиля и границ подтверждения.

Существующий runner — `tools/jv/capture-unified-order-all-seven-pr13e.ps1`. Он уже проверяет происхождение файла и снимает цены, строки заказа, клей, активатор, распределение по площади и части Front. Первый новый срез добавляет список адресов, которые runner берёт из манифеста, и независимое сравнение подсумм для F28=3. Windows с установленным Excel нужен для получения независимого снимка. В CI обычные node-тесты воспроизводят сравнения с сохранёнными результатами без Excel и без БД.

## Сценарии

| Срез | Как строить случаи и что проверять |
| --- | --- |
| Ветвления и контролы | Для каждой пары IF, IFS и CHOOSE подтвердить достижимость исходного предиката. Для LOOKUP/INDEX проверить первый и последний допустимый индекс, отсутствующий ключ, разрешение пустоты, тип результата и различия профиля. Fixtures должны записывать реальные первичные контроли, а не подменять ячейку с формулой. |
| Размеры и раскрой | Из формулы и справочника получить подтверждённые пороги min/max. При допустимом шаге проверить значение ровно на пороге и с каждой стороны. Сравнить резы, кромку, количество створок, целочисленные количества материалов, предупреждения и размерностные единицы. |
| Slider и Zigzag | Группы L3/L5/X3/X5, число полотен, парковка, варианты открывания, крепёж, материал заполнения, разные типы/размеры. Сочетать независимые контролы попарно, добавлять полные кортежи для зависимых условий. Отдельно неактивные нули и отсутствие обязательных входов N40/N41. |
| Front | F1 и F7, B26 пуст/1/2 с наблюдением исходного поведения, есть/нет двери, разные размеры, фрамуга, ручки, замки, доводчик, диапазоны зависимых C18:C24 и D18:D19. Сверять I23, активность BOM, стекло, работы и S38. |
| Стекло и отделка | Комплектация on/off, розница, отличия прайсов, варианты стекла и обработки. Сравнивать стоимость каждой позиции, скрытые промежуточные G31/H31 и влияние на итог. |
| Транспорт и заказ | F28=1/2/3, независимый B26, множество количеств, один слот и mixed/all-seven, фактор ПРМ, упаковки, монтаж и допработы, скидка, наценка, AA11:AA18. Проверить отсутствие двойного начисления. |
| Ошибки | Неполные параметры, недопустимые индексы, неправильный профиль, ошибочные источники REF/NA/DIV0 и охранные строки «ОШИБКА». Отдельно выделять отказ продукта подтвердить расчёт и ошибку, воспроизведённую в источнике. |

Генератор использует фиксированный seed, сортированный набор доступных значений и попарное покрытие. Обязательные исходные инварианты и ограничения валидации применяются до генерации; если правило достижимости ещё не доказано, сочетание сохраняется как кандидат с исходным наблюдением. Каждый составной тест воспроизводится по манифесту. Для непрерывных входов считать покрытие условий и контрольных границ. Доли вычисляются только относительно заранее зафиксированного набора ветвей или параметров.

## Условие открытия коммерческого расчёта

Перед изменением существующего API-ограничения подтвердить всю расчётную цепочку допустимой ветви в двух профилях, включая SKU, количество, допработы и итог. Привязать проверку версии правил и прайса к артефактам. Разрешённый статус DISPLAY_MATCH отражает только отображение, поэтому проверять денежную точность согласно явно согласованной политике и сохранять рациональные результаты. Нет данных, расходится итог, неизвестна активная ветвь или не подтверждён штатный механизм Excel — сохраняется ограничение. Успешный частный сценарий служит регрессией для своих входов.
