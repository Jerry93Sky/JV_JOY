# Zigzag: зависимости цен и коммерческих итогов

## Граф

```text
Z1 input/settings + #3 lookup
  └─ N5:N35 (ExactRational)
      ├─ O5:O35 ← raw per-profile literal price rows + D3/L7/L8
      │   └─ P5:P35 ← exact quantity × unit price
      │       ├─ P34 × Клей+акт!O5
      │       └─ P35 × Клей+акт!O18
      └─ P38 = SUM(P5:P35), only if all 31 costs exist

Order positions + N34/N35 × position quantity
  ├─ Клей+акт!N12/N25 → O5/O18 → P34/P35
  └─ ПРМ!AB25:AB31 → W5 → P39/P40 and optional P42 slot fee

P39 ← C8 selector, U10:U14 → U15, U17 → U18
P40 ← D32 → C9 glass selector + D28:D31/C29:C31 + glass D5:D16 → H26:H29 → H33
H23 guard ← G23 = D29/Настройки!L26-D4; H23="ОШИБКА" → C29="ОШИБКА" → H29/P40 Excel error (preserved as PARTIAL)
P41 ← D33 + L3 → width/C6 and N10/C19
P42 ← P38:P41 + (F28=2 ? C25×W5 : 0)
P43 ← D34 + width/height/leaf count + C8/C9/C13 service rates
P44 = P42+P43
```

## Входы и источники

- `O5:O35`: 31 строк каталога и прямых ссылок проверены для обоих оригинальных XLSM. Розничный и комплектационный snapshot различаются и имеют отдельные SHA-256/версии.
- `P39`: C8 зависит от `Главная!H11`. U10=`N10*G10`, U11=`N40*G39`, U12=`N41*G40`, U13=`SUM(U5:U12)*IF(C8=4,L11,1)`, U14=`L9*L10*W5`, U15=`MAX(U10:U14)`, U17=`C24*W5`, U18=`U15+U17`. Ветвь `C8=4` подтверждена независимым Excel-пересчётом с явно введёнными N40/N41=2/3 в обеих книгах. В оригинале N40/N41 пусты; это незаполненные ручные inputs, а не вычисляемые ячейки.
- `P40`: стекло выбрано через `Главная!I11` → `Z1!C9` → `'Прайс-Стекло'!D5:D16`. Геометрические H26:H29 и H33 рассчитаны заново, а H23 guard восстановлен из `G23=D29/Настройки!L26-D4`. Для `4200×2500`, 5 створок и selector открывания 3 Excel возвращает `G23=-377.911…`, `H23="ОШИБКА"`, `C29="ОШИБКА"`, `H29=#VALUE!`, `P40=#ЗНАЧ!` при активном D32. Engine сохраняет причину в diagnostic/trace, не превращает сбой в 0 и не публикует P44/Sslot. При выключенном D32 формула IF оставляет P40=0.
- `P41`, `P43` и F28 surcharge используют буквальные значения C6/C8/C9/C13/C19/C25 из версионированного источника `'Прайс-сб+монт'`.
- `W5` получается из `ПРМ!AB25`; область заказа зависит от размеров и количества всех строк Главная!11:17. Неизвестные семейства не исключаются из знаменателя.

## Ограничения проверенного покрытия

- Шесть двухпозиционных сценариев (три варианта на каждый прайс) закрывают многопозиционный P38:P44, включая конечные S11/S12, общие расходы и количество экземпляров. Это подтверждение указанных входов, не любых возможных комбинаций.
- Общая цена заказа не имеет исходной итоговой ячейки в книге. Excel контрольная ячейка `Main!ZZ100` создавалась только в одноразовой временной копии с формулой `=S11*Z11+S12*Z12`; три валидных заказа каждой книги совпали EXACT по binary64 или по display после форматирования. Оригинал не изменялся.
- Для активной стекольной ошибки downstream P42/P44/Sslot численно не подтверждаются: они ошибочны в Excel. Engine честно отдаёт PARTIAL. В parity отчёте 12 таких сравнений UNVERIFIED, при этом MISMATCH=0.
- Смешанное семейство остаётся PARTIAL: его расходы клея и активатора не включаются в точные N12/N25, пока не передан независимо подтверждённый расчёт этого семейства.
