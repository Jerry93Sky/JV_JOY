# Первичное профилирование результата JV

Повтор: `pnpm --filter backend build`, затем `node tools/jv/benchmark-result-http.mjs`. Скрипт запускает защищённые Fastify routes в изолированном процессе с временным секретом, без production БД; использует fixture all-seven, один прогрев и 8 конкурентных `inject`. Это однопроцессный синтетический прогон, не сетевой тест и не измерение серверного SLO. Сырые показатели: `JV_RESULT_BENCHMARK.json`.

Прогон на Windows x64, Node 24.13.0, AMD Ryzen 5 7500F (12 логических CPU), RAM 33,946,218,496 байт: 8 запросов за 746.9 мс, примерно 10.7 запроса/с, p50 355.9 мс, p95/p99 736.1 мс, ошибок 0, итоговые рациональные цены одинаковы. Для восьми измерений p95/p99 статистически неустойчивы. CPU процесса: 703 мс user + 110 мс system; средняя загрузка одного логического CPU по времени прогона около 109%, не измерение отдельных ядер. RSS 170.4 → 371.5 МБ, heap 39.0 → 136.2 МБ; это замеры до/после, не доказательство утечки и не точный пик. Event-loop delay max 746.1 мс; ответ примерно 3,153,987 байт.

Отдельный одиночный замер после прогрева: JV Engine 36.0 мс, `serializeJvResult` 25.2 мс, `JSON.stringify` 10.4 мс. Это отдельные выборки и они не суммируются непосредственно в latency HTTP. Синхронные BigInt-вычисления и рекурсивная подготовка/сериализация большого ответа выполняются в Node event loop. На данном прогоне нельзя установить долю CPU по ядрам, GC-паузы, устойчивость длительной нагрузки или ускорение от нескольких ядер.

Chrome E2E на all-seven: `JSHeapUsedSize` до расчёта 20,327,956 байт, после раскрытия общего BOM, отдельных разделов и первых 100 шагов trace 63,136,580 байт; около 3,743 DOM-элементов. Это разовый CDP-снимок, включает данные приложения и не является пиком памяти или тестом утечек. Сценарий повторяется через `pnpm --filter frontend test:jv-browser`.

Предлагаемые следующие шаги: сначала отдельный версионированный компактный DTO с явным набором разрешённых полей и постраничным trace, проверить эквивалентность BOM и цен; затем нагрузочный тест реального HTTP с изолированной БД и замерами 1/2/4/8 процессов или ограниченного worker pool, включая стоимость передачи данных, backpressure, отмену и квоты памяти. Worker не внедрён; многоядерное масштабирование и soak — NOT_RUN. Численные SLO не установлены.
