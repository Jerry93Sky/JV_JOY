# JV Result DTO v1

`POST /api/jv/orders/calculate-preview-v1` accepts the existing preview request and requires OWNER or ADMIN. It returns `schemaVersion: JV-RESULT-1`, correlation/order IDs, profile, engine and source versions, COMPLETE/PARTIAL, permitted BOM, position geometry and the explicitly selected commercial subtotals, diagnostics, limitations, per-scope traceCount and an opaque traceHandle. The total is included only for COMPLETE. Exact rationals are `{numerator,denominator}` decimal strings; no money is recalculated or rounded in the DTO or UI. Quantity is already order-scaled. A nullable handle means the bounded store could not admit the trace.

`GET /api/jv/orders/results/:handle/trace?position=&query=&offset=0&limit=100`: same role policy; handle bound to JWT user ID. Empty position selects order trace; otherwise exact position ID. In original engine order, query matches step ID, type, rule, sheet or cell case-insensitively. Max page 100, query and position max 100 chars. Response is `{steps,total,offset,limit}`. 400 invalid query; 404 unknown, expired, evicted or wrong owner; 401/403 auth. Responses use no-store. Trace is projected before storage; no arbitrary inputs, catalog contents or object results are returned. UI debounces 250 ms and cancels on changes or closure.

The per-process in-memory trace store retains at most 16 entries and 16 MiB of serialized trace, TTL 5 minutes, FIFO eviction, using 256-bit random handles. Expired entries are removed on next store access, so memory remains bounded even when idle. Restart or a request reaching a different process invalidates the handle; this version needs sticky routing in a multi-process deployment. Result calculations are not persisted. `calculate-preview` is unchanged and continues to provide the full legacy response to OWNER/ADMIN.
