# PR_04 — спецификация материалов JV-Line

## Статус на входе

PR_03E добавил независимый расчёт четырёх резов несущего профиля `L1!C28:D32` и количество `L1!O5` для `LN-010` («Профиль несущий», `п.м`). Геометрия I25/I26/I27, парковка O15 и оба PD lookup уже доступны в shared JV-DAG. PR_04 повторно пересчитал пять сценариев в обеих книгах Microsoft Excel 16.0 с отключёнными VBA-макросами: geometry/cuts совпали во всех 10, а точное сравнение O5 выявило 6 exact cases и 4 различия Excel binary representation. Полная BOM остаётся частичной. См. `LINE_MATERIAL_PARITY.json`.

## Цель PR_04

Сформировать точную, трассируемую **количественную спецификацию материалов и комплектующих для JV-Line** поверх подтверждённой геометрии. PR_03E output LN-010 использовать напрямую. Остальные строки добавлять только после непосредственной проверки Excel formula, ссылок на справочники и повторного сравнения golden cases.

## Обязательная работа

1. Исследовать downstream материал-позиции листов L1–L7: ссылки L/M/N (код, наименование, единица) и O (количество), используемые формулы количеств, условия включения и формульные источники справочников.
2. Проверить различия комплектации и розницы для каждой выбранной позиции: состав строки, единицы, формулы и ссылка на каталог. Не переносить цену, пока не построено отдельное verified price snapshot.
3. Определить действительное соответствие Excel `LN-*` и BMS `SystemComponent`/параметров. Если артикул, единица или quantity mapping не совпадает — фиксировать блокирующую конкретную ячейку/запись.
4. Использовать existing geometry/cutting results и общий calculation DAG; не копировать формулы I25/I26/I27 или D28:D32 в модуль спецификации.
5. Создать typed BOM/material lines для только доказанных строк: code ref, label, exact unit, quantity, source formula/cell, catalog version, trace-step IDs, parity status. Не считать материал по `cutCoeff` или округлённой длине, если Excel этого не делает.
6. Дополнять golden-сценарии Microsoft Excel через `tools/jv/recalculate-line-cutting-golden.ps1`. Макросы отключить, пересчитывать копии, сохранять в fixture только минимальные quantity/geometry outputs без prices.
7. Добавить unit/trace/conditional branch tests, Excel parity fixtures для обеих книг, обновить coverage и результат PR_04.

## Возможные соседние блоки для исследования

- `L1!O5` / LN-010 — уже подтверждённая строка несущего профиля; downstream cost/weight cells `Q5/S5/V5` не включать, пока не разрешён scope pricing/cost.
- Профили `LN-020/LN-030/LN-040` (`O6:O8`) расходуют отдельные геометрические правила и припуски; не назначать формулы до проверки всех их источников.
- Резы, заглушки, ролики, стекло, щётка и крепёж должны оставаться разными группами материалов/комплектующих; не объединять quantities с разными units.

## Ограничения

- Не менять legacy `/calculate`, Prisma schema, рабочую React UI, действующие BMS формулы/данные.
- Не включать цены, себестоимость, скидки и монтаж без отдельного технического контракта.
- Не создавать approximate fallback, SKU, коэффициенты и единицы.
- Не считать сохранённые caches исходных книг эталонами.
- Не коммитить от выдуманного автора. Сохранять уже существующие staged изменения.

## Критерии готовности

- Для каждого нового material line есть ссылка на обе оригинальные книги, точный Excel адрес, formula/constant, unit и исходный справочник.
- Golden cases подтверждают каждую перенесённую quantity branch для комплектации и розницы.
- Результат формирует прослеживаемую спецификацию без стоимости и без перехода на production API.
- `docs/jv/PR_04_RESULT.md` фиксирует внедрённые строки, тесты, Excel runs, расхождения с legacy и оставшиеся неизвестные входы.
