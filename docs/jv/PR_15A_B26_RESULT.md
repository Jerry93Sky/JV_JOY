# PR_15A: независимый контекст B26

В обоих XLSM формула `F7!S36` проверяет `Главная!B26`, тогда как `F1:F6!S36` проверяет F28. Эти входы разделены: движок принимает версионированный `frontSlot7B26` с адресом, SHA-256 и происхождением; он валидируется против источника книги. При F28=2 и отсутствии B26 движок по-прежнему отклоняет расчёт. Для API B26 предоставляется только серверным профилем `JV-PR13E-B26-SCENARIO-1`: значение 1 является **явным вводом контрольного сценария PR13E**, а не исходным значением оригинальной книги, где ячейка пуста. Клиент не может его менять. Trace `F7!S36` сохраняет настоящий адрес, формулу и версию селектора.

Текущий подтверждённый UI-профиль разрешает Front в слоте 7 при F28=2 и B26=1. Это не предоставляет пользователю редактирование B26 и не подтверждает произвольные профили. Сервер заполняет порядок и источник для каждой Front-позиции, включая дубли.

12 ранее независимо пересчитанных all-seven F28=2/B26=1 сценариев повторно сравнены с исправленным движком: 84 строки AA11:AA17 — 32 NUMERICALLY_EQUIVALENT и 52 DISPLAY_MATCH; 12 итогов AA18 — 1 NUMERICALLY_EQUIVALENT и 11 DISPLAY_MATCH. 0 MISMATCH и 0 UNVERIFIED. Результаты сохранены в `JV_UI_F28_PARITY.json`; повторное использование прежних Excel-выгрузок не является новым пересчётом.

Новый Excel 16.0 `CalculateFullRebuild` на временных копиях обеих книг: по одному исходному all-seven сценарию на профиль, все 4 сочетания F28=1/2 и B26=1/2, итого 8 пересчётов. Сравнены `F7!Y5`, `S36`, `S38`, `Главная!AA17`, `AA18`: 40 сравнений — 14 NUMERICALLY_EQUIVALENT, 26 DISPLAY_MATCH, 0 MISMATCH и 0 UNVERIFIED. Исходные данные и SHA-256: `fixtures/front-slot7-b26-r2-excel.json`, отчёт `FRONT_SLOT7_B26_R2_PARITY.json`; скрипты `tools/jv/capture-front-slot7-b26-r2.ps1` и `tools/jv/compare-front-slot7-b26-r2.mjs`. DISPLAY_MATCH не является точным числовым равенством.

PR_15A остаётся PARTIAL: серверный профиль двери I42=2, другие варианты фурнитуры и оставшиеся сочетания селекторов не подтверждены для UI. Новые проверки не подтверждают их автоматически.

Локально прошли сборки backend/frontend, shared typecheck, 205 JV-тестов, 10 API-тестов, React HTTP integration, Chrome E2E, проверка 50 fixtures и Line Lab smoke. Браузерный сценарий проверяет Front в слотах 2 и 7 при F28=2, включая пересчёт и отсутствие устаревшего итога.
