# JV-Front: карта стоимости для PR_12B

PR_12A не вычисляет цену. Ниже зафиксированы зависимости исходных Excel, чтобы перенос коммерческой цепочки был проверяемым. Полный извлечённый набор формул `F1!R/S/U/W/X/Y` сохранён в `packages/shared/src/jv/front/source-price-formulas.ts`.

```text
F1!Q5:Q32 ─┬─ F1!R5:R32 ─> F1!S5:S32 ─> S33 ─┐
           ├─ Прайс-Front!F/G5:F/G18 ─> U19/U20, W19/W24 ─> S34
Стекло C28:I32 ─> H32 ─> D35 ─> S35 ───────────────┼─> S36 ─┐
Прайс-сб+монт!C16:C18, D3, C17, Q27 ─> S37 ───────┘       ├─> S38
I23 (ошибка) ─────────────────────────────────────────────────┘
S38 ─> Главная!X11 ─> Y11 ─> AA11 ─> AA18/F32/F36
```

Материалы: `F1!R5:R18` читают `Прайс-Front!E5:E18`, для метровых строк делят на `Настройки!D5`. `R19:R26` используют множители `Прайс-Аксессуары!F51:F58*E51:E58`. `R27:R30` выбираются через `INDEX` по `C21:C24`. `R31:R32` читают `Прайс-Front!E19:E20`. `S5:S32` обычно `Q*R`, но `S6=P6*R6*2*ROUNDUP(C3/1000,0)` — подтверждённое исключение. Артикулы, наименования и единицы справочников в двух книгах совпали по проверенным Front-строкам; сами цены для PR_12B нужно версионировать отдельно для комплектации и розницы.

Стекло: `H28:H31` считают площадь по `C*D*E*G/1000000`, `H32=SUM(H28:H31)`, `D35=H32+'Прайс-сб+монт'!C23*Y5`; `S35=IF(Настройки!D32,D35,0)`. `Y5=ПРМ!AB25`. Покраска: `U5:U18` используют `Q*'Прайс-Front'!F`, `U19=SUM(U5:U18)`, `U20=U19+D32`; `W5:W18` используют `Q*'Прайс-Front'!G`, `W19` применяет `Настройки!L11` при `C6=4`, `W20=Настройки!L9*L10*Y5`, `W21=MAX(W18:W20)`, `W23='Прайс-сб+монт'!C24*Y5`, `W24=W21+W23`, `S34=IF(C6<>1,W24,0)`.

Дополнительные работы: `S36=SUM(S33:S35)+IF(Главная!F28=2,'Прайс-сб+монт'!C25*Y5,0)`. Монтаж: `S37` зависит от `Настройки!D34`, `D3`, `C17`, `Q27` и `'Прайс-сб+монт'!C16:C18`. Итог `S38=IF(I23="ОШИБКА!",I23,SUM(S36:S37))`. В `Главная!X11` он делится на `Настройки!D14`, затем `Y11` применяет `D21`, а `AA11` — количество `Z11` и `D19`.

Общие расходники: на листе `Клей+акт` `C5=Главная!G11`, `L5=IFERROR(INDEX(E5:K5,C5),0)` и аналогично `L18` для клея. Для `G11=7` выбираются `K5=0` и `K18=0`; собственные потребности Front на конструкцию равны нулю и представлены в результате калькулятора. `N5=L5*Главная!Z11`, `N18=L18*Z11`; `N12/N25` округляют общую закупку. Для Front это не означает право подставлять расход Slider.

В `ПРМ` есть связи `I11=F1!D33`, `R11=F1!U20`, `AA11=F1!D34/F1!C5`, однако `ПРМ!R25=IFERROR(IF(L25=7,'F1'!#REF!,0)*Главная!Z11,0)` содержит исходную битую ссылку `#REF!`. Аналогичные формулы встречаются для `F2:F7`. Перед реализацией `Y5` и коммерческого результата требуется отдельно определить фактическое поведение этого узла в обеих книгах на пересчитанных сценариях; нельзя трактовать сохранённый ноль как подтверждённый бизнес-замысел.

Риск финансового округления Slider-X5 `S1!R10` из PR_11J остаётся отдельным и не изменяется в PR_12A.
